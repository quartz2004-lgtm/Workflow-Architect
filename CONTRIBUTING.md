# Участие в разработке

Workflow Architect развивается небольшими проверяемыми этапами. Текущая область работ — [план 0.2.0](docs/V0.2.0_PLAN.md); будущие возможности определяет [roadmap](docs/ROADMAP.md).

## Перед изменением

Прочитайте [AGENTS.md](AGENTS.md), соответствующие разделы [спецификации](docs/Workflow_Architect_v0.1_Specification.md) и [реализованную архитектуру](docs/ARCHITECTURE.md). Существенное расширение продукта сначала обсуждается как предложение. Не добавляйте runtime, выполнение команд или интеграции в патч редактора.

Создайте ветку `fix/краткое-имя` или `feature/краткое-имя`. Один PR должен решать одну понятную задачу. Сохраняйте разделение Canvas, domain, editor commands, storage и exporters. Формат проекта версионируется независимо от версии приложения; изменение формата требует миграции, backup и фиксированных примеров старых данных.

## Локальная проверка

Требуются Node.js 24+ и npm. Используйте lockfile:

```sh
npm ci
npm run check
npx playwright install chromium
npm run test:e2e
```

Каждый новый скрипт должен начинаться с уведомления из docs/COPYRIGHT_NOTICE.txt. npm run copyright:fix добавляет комментарии, npm run copyright:check проверяет их, включая новые неотслеживаемые файлы. Генераторы сохраняют уведомление; сторонние файлы не перелицензируются.

После изменения справки выполните `npm run docs:almanac`. После изменения зависимостей — `npm run notices:generate`; проверьте изменения лицензий и тексты уведомлений. На Windows дополнительно выполните `npm run desktop:prepare` и `npm run test:desktop`. Изменения установщика проверяйте командами из [DESKTOP.md](docs/DESKTOP.md). Performance-проверки запускайте отдельно, без параллельной нагрузки.

Добавляйте проверки поведения, которое может сломаться: история, сериализация, импорт, конфликт сохранения, миграция или взаимодействие пользователя. Для UI проверьте фокус, клавиатуру, reduced motion и окно 1000×700. Не сохраняйте секреты, реальные профили пользователей и сборки в Git.

## Описание PR

Укажите проблему, итоговое поведение, выполненные проверки и оставшиеся ограничения. Для UI приложите изображение без личных данных. Для архитектурного изменения обновите ARCHITECTURE.md и при необходимости добавьте ADR. Не объединяйте PR с падающими обязательными проверками и не переписывайте опубликованные release tags.

Ошибки описывайте через шаблон Bug report. Сообщения об уязвимостях направляйте по [SECURITY.md](SECURITY.md), без публичного размещения чувствительных материалов.
