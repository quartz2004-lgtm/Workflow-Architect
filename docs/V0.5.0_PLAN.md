# Выпуск 0.5.0 — интеграции и удалённая работа

Статус: разработка. База: 0.4.0, commit d1b8824. Пользователь 14.10.2026 выбрал Telegram для создания и изменения статей и управления задачами; дополнительный сервис публикации не выбран. Это уточнение заменяет пункт roadmap об отдельном веб-сервисе. MCP выбирается разработчиком: официальный filesystem server, только явно разрешённая папка статей.

## Архитектура и порядок

1. **Контракты.** Версионируемые декларативные операции и каталог интеграций. Проект содержит параметры, schemas и ссылки на подключения, но не секреты, локальные разрешения или команды процессов. Старые форматы заморожены; миграция сохраняет исходный backup.
2. **Доверенная граница.** Адаптеры HTTP/JSON, файлов, Telegram и MCP живут в native runtime. Credentials разрешаются через main-процесс для конкретного профиля; права перепроверяются при действии. UI получает состояния и проверенные результаты. Запись внешнего эффекта фиксируется до запроса; неизвестный результат после сбоя не повторяется автоматически.
3. **Входные события.** Долговечные подписки на неизменяемые версии workflow, расписание и Telegram long polling. Входящие события регистрируются до продвижения offset, дедупликация использует устойчивый ключ события. Удалённый пользователь связан с профилем; чужой чат/просроченное подтверждение не дают доступ к запуску.
4. **Telegram для статей.** Создание текста, запрос правок к предыдущему результату, получение файла, список разрешённых процессов, статус, отмена, ответы Human. Естественный язык выбирает только из разрешённых намерений и workflows; shell и изменение прав недоступны.
5. **Рабочий интерфейс.** Каталог, формы подключения и проверки, выбор credential, разрешённых папок и MCP tools, настройка Trigger/Tool, визуальное сопоставление полей и примеры payload. Отдельное включение подписки, явные состояния «секрет сохранён», «подключение проверено», «слушает сообщения». Альманах и готовые примеры.
6. **Приёмка и выпуск.** Unit/integration/browser/desktop, typecheck/lint/build/copyright/notices; реальные Telegram + Ollama + MCP; два профиля, повторы событий, обрыв сети, отзыв прав, перезапуск, неизвестный исход внешней записи. Backup перед обновлением, проверка установленного exe, CI, tag, GitHub release и проверка assets.

## Критерии и ограничения

- Каждый обязательный пункт ROADMAP 0.5.0 сохраняется, кроме явно заменённого выбора дополнительного веб-сервиса.
- Текстовые личные Telegram-чаты, без публичного входящего webhook. Голос и мультимедиа-обработка остаются последующим этапом; текстовые файлы и артефакты входят в 0.5.0.
- Секреты не попадают в snapshots, журналы, ошибки, prompts или exports. Ответ внешнего сервиса — недоверенные данные.
- Доступ к файлам ограничен корнями и проверкой фактических путей, включая junction/symlink; сеть ограничена явно выбранным назначением. Импорт проекта не создаёт разрешений.
- MCP запускает выбранный доверенный сервер, а не shell из параметров графа. Обнаруженные tools не разрешаются автоматически; изменения их контрактов требуют повторного выбора.
- Расписание не воспроизводит бесконтрольно все пропущенные события после сна. Внешние записи с неизвестным исходом требуют сверки, а не скрытого retry.
- Нельзя заменить реальную приёмку только mock-тестами. Если для неё потребуется участие владельца/жены или настройка отсутствующего подключения, задать конкретный вопрос и остановить работу согласно указанию пользователя.

## Технические источники

- [Telegram Bot API](https://core.telegram.org/bots/api): long polling, update offset, callbacks, сообщения и документы.
- [MCP transports](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports): изолированный stdio клиент и жизненный цикл.
- [Официальный filesystem server](https://github.com/modelcontextprotocol/servers/tree/main/src/filesystem): разрешённые каталоги; версия фиксируется в lockfile после проверки.
