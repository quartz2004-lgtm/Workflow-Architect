# 0.5.1 — понятная настройка Telegram

Статус: разработка. База: принятая владельцем 0.5.0, ветка development/0.5.1. Полный объём — раздел 0.5.1 в ROADMAP.md.

## Последовательность и границы

1. Проверка совместимости Telegram-входа в application layer; одно действие публикации и назначения чату с проверкой профиля и ожидаемой старой публикации. Ошибка не меняет работающую привязку. Durable project format и Canvas не меняются.
2. Единый мастер в Интеграциях: существующий либо новый защищённый секрет → проверка бота → привязка личного чата → проверенный сценарий → тест. Не выводить секрет в runtime integration protocol, snapshots или logs; использовать существующий credentials IPC.
3. Карточка активного сценария с датой/идентификатором версии для человека, признаком изменений Canvas и явным подтверждением обновления. UUID остаются только в дополнительных сведениях.
4. Кнопки бота для нового текста, правок, сценария, статуса и файла. Состояние диалога ограничено привязанным пользователем; Human подтверждения не смешиваются с навигацией. Сообщения и ошибки называют сценарий и следующий шаг.
5. Обновление альманаха, README, архитектуры; unit/integration/browser/desktop, типы, lint, copyright, production build, проверка UI и реального установленного приложения. Backup перед обновлением. Приёмка двух профилей, CI, Git tag и опубликованный GitHub Release с установщиком и SHA256.

## Обязательная приёмка

- Настроить Telegram из одного окна без ручного переноса ID и перехода в отдельный vault dialog.
- Сохранённый токен, проверенный бот, привязанный чат и включённый сценарий явно различаются.
- Первый локальный пример с `/approved` отклоняется для обычного сообщения до назначения; доступны подходящий шаблон и объяснение.
- Нельзя назначить чужой workflow, изменить чужую привязку или затереть конкурентное изменение. Ранее опубликованный snapshot сохраняется.
- Изменение Canvas не скрыто меняет remote run; интерфейс показывает различие и предлагает обновление.
- Кнопки бота работают без UUID и без локальной модели для навигации. Неверные/чужие/устаревшие callbacks не дают полномочий.
- Оба пользователя самостоятельно проходят показанный приложением путь; получение статьи/правок и Human подтверждения сохраняются.
- Release действительно опубликован, assets доступны и соответствуют проверенной сборке. До этого goal не завершён.

## Проверки и результаты

- Первый этап: добавлены application preflight и native команды preflight/activate. Несовместимый `/approved` отклоняется до назначения; ранее опубликованный snapshot сохраняется. Проверены чужой профиль, устаревший выбор и сохранение привязки после ошибок. Проверка динамических выходов не заявляется полной: UI должен показать предупреждения и предложить тест.
- `npm run check`: 207 тестов / 44 файла, typecheck, lint, copyright/notices и production build прошли. Интерфейс мастера, бот-кнопки, упаковка и выпуск 0.5.1 ещё не выполнены.
- Второй этап: единый TelegramPanel объединяет защищённый ввод токена (через существующий credentials IPC), проверку бота, pairing, выбор сценария и тестовое сообщение. TelegramScenario открывает готовые проекты через switchProject/autosave, показывает активную неизменяемую версию и различие с Canvas, выполняет activate по явному подтверждению. Добавлен готовый Human-сценарий, совместимый с сообщениями.
- Сквозной браузерный тест использует настоящие IntegrationService/SourceStore/JobManager с подменой только Telegram transport и браузерного credentials bridge. Пройдены ввод с разрешением, pairing, блокировка `/approved`, создание готового проекта, activate, тестовое сообщение, изменение Canvas и подтверждение новой версии при сохранении старой. UI просмотрен при 1440 и 850 px. Desktop credentials/MCP: 2/2. Меню бота, окончательная документация, полная приёмка и выпуск пока впереди.
