Что такое Workflow Architect

Назначение, результат работы и возможности версии 0.1.

Workflow Architect — рабочая среда для проектирования AI-систем и мультиагентных процессов. Здесь вы описываете, кто решает задачу, какие данные получает, какими инструментами пользуется и кому передаёт результат. Архитектура видна на Canvas и одновременно хранится как структурированный проект.

Приложение помогает превратить расплывчатую идею в понятное задание для реализации. Начните с простых блоков, уточните ответственность каждого шага, задайте контракты и передайте результат разработчику или coding-agent.

Идея → Concept Graph → Engineering Graph → Спецификация → Экспорт

Когда оно полезно

  • Перед разработкой: договориться о границах системы, ролях агентов и ожидаемом результате.
  • При сложном процессе: увидеть переходы, общие данные, ручные проверки и вложенные подсистемы.
  • При передаче задачи: собрать граф, инструкции, схемы и план реализации в один пакет.
  • При пересмотре архитектуры: менять структуру, отменять правки и проверять ссылки без запуска сервисов.

Что вы получаете

Сохраняемый локальный проект, визуальную схему, описания узлов, prompts, JSON Schemas, диагностику и экспортируемые спецификации. Windows-приложение работает офлайн и не требует аккаунта.

В версии 0.1 агенты, API, расписания и выражения описываются, но не выполняются. Preview показывает обход архитектуры. Codex package создаёт файлы для передачи coding-agent; автоматического подключения к Codex в приложении нет.

Этот альманах описывает реализованный интерфейс Alpha 0.1 и Windows-оболочку. Английские названия оставлены там, где они встречаются на кнопках и в полях. Оглавление слева и поиск работают без интернета. «Сохранить альманах» выгружает весь справочник одним HTML-файлом с оглавлением для чтения и печати.

Первый проект за 10 шагов

Практический маршрут от пустого Canvas до резервной копии.

  1. Откройте Workflow Architect через ярлык Windows. Нажмите название проекта сверху: появится менеджер «Локальные проекты».
  2. Введите название и нажмите «Создать пустой проект». Например: «Исследование темы».
  3. Нажмите Concept Node слева три раза. Выделяйте узлы и в Inspector задайте им названия «Получить вопрос», «Исследовать», «Подготовить ответ». После ввода нажмите Enter или перейдите в другое поле.
  4. Переместите карточки так, чтобы читать цепочку было удобно. Соедините выход первого узла со входом второго, затем второй с третьим.
  5. Для каждого узла добавьте описание: что он получает, что делает и что должен вернуть. Пока технические параметры не обязательны.
  6. Выделите «Получить вопрос» и выберите «Преобразовать в» → Trigger. В Trigger type выберите manual. «Исследовать» преобразуйте в Agent, последний блок — в Artifact.
  7. У Agent заполните роль, System prompt, Provider и Model. У Artifact задайте тип document и формат Markdown. Значения модели описывают будущую реализацию; запрос к ней не отправляется.
  8. Добавьте входной и выходной контракты Agent. Для начала подходит «Свободное описание»: «Вопрос пользователя» и «Ответ с источниками».
  9. Нажмите Validate. Откройте замечания, исправьте ошибки и осознанно оставьте допустимые предупреждения. Preview поможет просмотреть структуру переходов.
  10. Нажмите «Экспорт» → JSON snapshot → «Скачать экспорт». Сохраните резервную копию. Для передачи на реализацию выберите Codex package.
Переключатель Concept / Engineering сверху сам по себе не преобразует узлы. Тип каждого Concept меняется отдельно через Inspector, контекстное меню или палитру.

Более быстрый старт

В менеджере проектов выберите Multi-agent Research, Content Pipeline или Automation Concept. Создаётся самостоятельный проект с новыми ID. Это редактируемые примеры архитектуры, а не готовые исполняемые приложения.

Inspector и правила ввода

Общие поля, статусы, применение текста и JSON, настройки проекта.

Inspector меняется в зависимости от выделения. Один узел показывает его общие и специализированные поля; связь — тип и контракт; группа — управление группой; несколько объектов — массовые действия. Без выделения доступны свойства проекта.

Общее полеНазначение
НазваниеКороткая подпись; до 300 символов.
ОписаниеСмысл и ответственность элемента.
ЗаметкиДополнительные решения, вопросы и критерии.
ТегиМетки через запятую; используются в поиске.
СсылкиHTTP/HTTPS-адреса, по одному на строку.
Цвет акцентаВизуальное выделение, которое не меняет семантический тип.
Статусdraft — черновик; configured — настроен; ready — готов по вашей оценке; disabled — выключен.

Когда изменение считается применённым

  • Обычный текст применяется при потере фокуса. Enter применяет однострочное поле. Для многострочного текста перейдите в другое поле.
  • Списки вроде правил поведения заполняются по одному элементу на строку. Переключатели и select применяются сразу.
  • В JSON-поле «Форматировать» проверяет и оформляет текст; «Применить JSON» сохраняет его в проект. Ошибка JSON показывается рядом с полем.
  • Autosave сохраняет уже применённые изменения. Недописанный JSON не становится частью проекта только потому, что сверху отображается «Сохранено».
  • В Windows при штатном закрытии активное текстовое поле теряет фокус, после чего приложение ждёт autosave. При проблеме сохранения предлагается вернуться в редактор.
Статус ready задаёт пользователь. Он не доказывает отсутствие ошибок, доступность модели или готовность исполняемого приложения. Проверяйте Validate отдельно. Временная подсветка Preview также не означает реальный успешный вызов.

Группы, поиск и история

Организация больших графов, копирование и отмена действий.

Группы

Выделите несколько узлов и нажмите G. Группу можно назвать, описать, перекрасить, переместить и свернуть. Перемещение группы переносит участников. Сворачивание упрощает вид; оно не удаляет содержимое.

«Разгруппировать» сохраняет узлы на Canvas. «Удалить группу с узлами» удаляет содержимое. Перед действием смотрите его полное название. При ошибке используйте Ctrl+Z в той же сессии.

Копирование и дублирование

Ctrl+C / Ctrl+V копируют и вставляют выделение; Ctrl+D дублирует его. Новые элементы получают новые ID. Внутренние связи и нужные ресурсы копируемой структуры переносятся; внешние ссылки требуют внимания, особенно при переносе между проектами. Буфер редактора локален текущему окну/вкладке и не является системным обменом workflow между приложениями.

Поиск и команды

Ctrl+F открывает поиск по проекту, включая вложенные графы: названия и типы узлов, теги, названия/описания групп и названия графов. Полный текст prompts и всех конфигураций этим поиском не индексируется. Выбор результата открывает нужный граф и показывает объект. Ctrl+K или Space открывает палитру действий: создание, преобразование, навигация и организация. Доступность команды зависит от выделения.

Undo / Redo

Ctrl+Z отменяет создание, удаление, перемещение, размеры, правки полей, связи, группы, преобразования и сохраняемые настройки. Ctrl+Shift+Z повторяет отменённое. История ограничена 200 операциями и живёт в текущей сессии: после открытия другого проекта или перезапуска не заменяет резервную копию.

Масштаб, наведение и временные окна не записываются как изменения проекта. Операции с вложенным графом учитывают его контекст. Любая правка модели останавливает Preview, чтобы он не показывал устаревшую структуру.

Concept и Note: начать с идеи

Лёгкие блоки, заметки и постепенное превращение замысла в систему.

Concept Node — шаг, идея или ответственность без обязательной технической конфигурации. Назовите его глаголом и результатом: «Проверить источники», «Согласовать публикацию». Описание отвечает на вопрос «что должно произойти», заметки хранят уточнения и нерешённые вопросы.

Связывайте Concept между собой ещё до выбора инструментов и моделей. Когда ответственность понятна, выберите в Inspector «Преобразовать в» и нужный engineering type. Сохраняются ID, название, описание, заметки, цвет, положение, размер и существующие связи. Преобразование можно отменить.

Note — пояснение для читателя схемы: гипотеза, ограничение, критерий готовности или решение. Заметка не имеет портов и не включается в обход Preview. Используйте её для контекста, который не является отдельным шагом процесса.

Agent: роль, модель и инструкции

Полная конфигурация AI-участника и пример хорошего prompt.

Agent описывает участника, которому будущая реализация поручит интеллектуальную задачу. Один агент — одна понятная ответственность. Например, Researcher собирает сведения, Critic проверяет аргументы, Writer готовит текст.

Пример System prompt

Ты — исследователь источников.

Subworkflow: вложенная система

Внутренний Canvas, открытые порты и границы подсистемы.

  1. Создайте Subworkflow из библиотеки либо выделите группу и нажмите «Преобразовать в Subworkflow».

Контракты и JSON Schema

Как договориться о форме данных и не спутать схему с примером.

Контракт — договор между частями системы о том, что они передают и ожидают. Он может находиться у узла, связи или порта. Само совпадение названий элементов не задаёт контракт.

ФорматКогда использовать
Свободное описаниеКогда смысл понятен, а поля ещё уточняются: «Ответ с проверяемыми источниками».
JSON SchemaКогда нужна локальная формальная структура конкретного входа, выхода или связи.
Общая схемаКогда один договор используют несколько узлов и связей; определение хранится в ресурсах проекта.

Пример схемы ответа

{
  "type": "object",
  "properties": {
    "summary": { "type": "string" },
    "sources": { "type": "array", "items": { "type": "string" } }
  },
  "required": ["summary", "sources"],
  "additionalProperties": false
}

type задаёт тип значения; properties описывает поля объекта; required перечисляет обязательные поля; items задаёт элементы массива; additionalProperties: false запрещает неперечисленные поля. Это схема, а не сам ответ агента.

Назначить общую схему

  1. Откройте «Схемы и prompts» слева.
  2. Нажмите «＋ Общая схема», задайте имя и JSON Schema.
  3. Нажмите «Применить JSON». Закройте окно ресурсов.
  4. В нужном контракте выберите «Общая схема», затем созданное имя.

По умолчанию используется JSON Schema draft-07. Для 2020-12 задайте $schema: https://json-schema.org/draft/2020-12/schema. Внешние метасхемы не загружаются. Переименование общего ресурса сохраняет ссылки, поскольку они основаны на ID.

Проверка обнаруживает некорректную JSON Schema и потерянные ссылки, но не доказывает полную логическую совместимость произвольных схем. Редактор не выполняет поток данных и не валидирует фактические ответы модели.

Общие schemas и prompts

Переиспользование, редактирование и связь ресурсов с узлами.

Ресурсы принадлежат проекту целиком и доступны вложенным графам. Общая схема задаёт повторно используемый контракт; общий prompt хранит инструкции, на которые ссылаются агенты.

  1. Откройте «Схемы и prompts» внизу библиотеки либо «Общие схемы и prompts» в свойствах проекта.
  2. Создайте ресурс кнопкой «＋ Общая схема» или «＋ Общий prompt».
  3. Выберите его слева, задайте понятное название и содержимое.
  4. Для схемы примените JSON. Для prompt используйте редактор, при необходимости разверните его или сохраните .md-файл.
  5. У Agent укажите Prompt reference; у контракта выберите формат «Общая схема».

Изменение общего ресурса влияет на все ссылающиеся элементы при дальнейшем чтении и экспорте. Переименование безопасно для ссылок; копирование текста в несколько локальных полей не создаёт такую связь.

Удаление используемого ресурса может быть отклонено, чтобы не создать новую повреждённую ссылку. Сначала уберите или замените ссылки. Создание, изменение и удаление ресурсов входят в undo/redo.

Если у агента заданы и Prompt reference, и System prompt, экспортируемый prompt включает общий текст, затем локальные инструкции. Проверьте, что они не противоречат друг другу.

Preview: прочитать ход архитектуры

Обход, пауза, шаги, ветви, вложенные графы и ограничения симуляции.

Нажмите Preview, чтобы просмотреть структурный обход текущего графа. Узлы подсвечиваются по очереди, связи показывают переходы. Панель сообщает текущий шаг и позволяет остановиться, продолжить, перейти к следующему шагу и показать текущий узел.

Проекты, autosave и импорт

Локальное хранение, перенос между ПК и резервные копии.

Название проекта сверху открывает менеджер локальных проектов. Здесь можно переключиться на сохранённый проект, создать пустой, начать с примера или импортировать файл. Открытие другого проекта сначала требует сохранить текущий.

Autosave

Применённые изменения записываются локально с небольшой задержкой. «Сохранено» означает успешную запись текущей версии. При ошибке появляется сообщение и кнопка повтора. До успешного сохранения не считайте изменения защищёнными от аварийного завершения или отключения питания.

В Windows данные находятся в профиле %APPDATA%\Workflow Architect, в IndexedDB. Установленное приложение открывает последний проект. Штатное закрытие ожидает сохранения; если оно не подтверждено, можно вернуться в редактор. Деинсталлятор сохраняет профиль.

Браузерная версия хранит данные отдельно для своего origin. Desktop не читает проекты браузера автоматически. Другой адрес/порт браузера или другой профиль Windows — другое хранилище. Для переноса используйте экспорт и импорт.

Импорт

  1. Откройте менеджер проектов и выберите файл через «Файл проекта».
  2. Передайте JSON/YAML snapshot, ZIP-архив или сразу два файла project.json + workflow.json.
  3. Прочитайте предпросмотр и сообщения. Нажмите «Открыть импорт».
  4. Проверьте Validate и дождитесь статуса «Сохранено». При совпадении ID с локальным проектом создаётся независимая импортированная копия.

Резервное копирование

Перед большими изменениями сохраните JSON snapshot в отдельную папку с датой в имени. Для другого ПК установите приложение и импортируйте этот файл. Копировать внутренние файлы IndexedDB вручную для обычного переноса не требуется. Autosave не заменяет отдельную резервную копию.

Восстановление и типовые проблемы

Что делать с повреждённым проектом, ошибкой сохранения или импорта.

Повреждённый проект

Если сохранённые данные не удаётся открыть, приложение показывает экран восстановления и сохраняет доступ к исходному JSON. Для распознаваемого JSON версии 0.1 оно пытается выделить совместимые данные и показывает отчёт: какие поля или объекты потребовали исправления.

  1. Сначала скачайте исходный JSON, особенно если проект важен.
  2. Прочитайте список проблем и предложенное восстановление.
  3. Если доступно, выберите «Открыть восстановленную копию». Она получает отдельный ID; оригинал не перезаписывается.
  4. Проверьте узлы, связи, schemas и prompts по отчёту. Исправьте оставшиеся замечания через Validate.
  5. Сохраните исправленный snapshot отдельно. Завершение recovery mode скрывает отчёт, но не является автоматическим исправлением всех решений.

Неразбираемый JSON и неизвестная версия формата не восстанавливаются догадками. Исходный файл остаётся доступным. Можно повторить загрузку или создать новый проект.

Примеры и приёмы проектирования

Три шаблона и способы превратить их в собственную архитектуру.

Multi-agent Research

Request → Planner → Researcher → Critic → Writer

Подходит для исследовательских задач. Planner разбивает вопрос, Researcher собирает сведения, Critic проверяет выводы, Writer оформляет ответ. Определите, что каждый шаг добавляет к общему контракту. В примере модель нужно выбрать отдельно; Warnings напоминают об этом.

Content Pipeline

Brief → Research → Copywriter → Editor → Artifact

Подходит для подготовки материалов. Уточните аудиторию, ограничения, формат результата и критерии редакторской проверки. Если публикацию должен разрешить человек, добавьте Human перед Artifact или инструментом публикации.

Automation Concept

Webhook → Router → Agent → Human Approval → API Tool

Подходит для обсуждения будущей автоматизации. Зафиксируйте входное событие, маршрутизацию, интеллектуальный шаг и точку согласования перед внешним действием. Сам webhook и API остаются описанием.

Полезные привычки

  • Начинайте с результата: что будет считаться завершённой задачей?
  • Один узел — одна ответственность. Длинное «и ещё…» в описании часто указывает на необходимость разделения.
  • Отделяйте управление от данных: Flow отвечает «куда дальше», Data — «что передаём».
  • Общие контракты храните в resources, чтобы переименование не ломало ссылки.
  • Группируйте для чтения; переходите к Subworkflow, когда ясна граница подсистемы.
  • Записывайте допущения и нерешённые вопросы в Note и заметках.
  • Сохраняйте snapshot до крупной перестройки и проверяйте экспорт глазами перед передачей.

В альманахе поиск фильтрует главы по заголовку и содержимому. Выберите главу в оглавлении; кнопки внизу переходят к предыдущей и следующей. Escape закрывает справку и возвращает фокус в редактор.

Границы версии и частые вопросы

Что уже работает, что не выполняется и что не следует ожидать от Alpha.

Можно ли прямо здесь запустить AI-систему?

Нет. Можно спроектировать её, проверить структуру, просмотреть обход и экспортировать спецификацию. Вызовы LLM, выполнение инструментов и кода, очереди, планировщик и production runtime не входят в v0.1.

Нужны ли интернет, аккаунт и API-ключ?

Установленное Windows-приложение работает офлайн. Аккаунт и ключ для проектирования не нужны. Реальные секреты не должны попадать в проект. Для сборки приложения из исходников интернет нужен при первоначальной загрузке зависимостей.

Поддерживаются ли совместная работа и синхронизация?

Нет облачной синхронизации, командных прав, комментариев, Git-интеграции и автоматической синхронизации кода с Canvas. Передавайте snapshots или пакеты вручную.

Почему после ready остаются предупреждения?

Статус узла задаётся вручную. Диагностика независимо проверяет структуру и обязательные инженерные поля. Изменение цвета или статуса не заполняет конфигурацию.

Можно ли использовать другой редактор или будущий runtime?

Экспорт хранит самостоятельную модель проекта с версией и стабильными ID. Это основа для внешних инструментов, но готовая совместимость с произвольным runtime, n8n или MCP не заявляется.

Какой размер графа разумен?

Ориентиры v0.1 — плавная работа около 100 узлов и пригодность около 300. Реальная скорость зависит от ПК, текста и связей. Большие схемы удобно делить на Subworkflow и использовать поиск; числовые лимиты формата не являются обещанием удобной работы на максимуме.

Как обновить Windows-приложение?

Автообновления нет. Сохраните snapshot важных проектов, штатно закройте приложение и установите новую сборку. Локальная Alpha не подписана сертификатом издателя. Для обычной работы используйте ярлык Workflow Architect; запускать dev server не требуется.

Что не сохраняется в проектный файл?

История undo, текущий Preview, открытые окна, временное выделение и состояние просмотра справки. Закрытие альманаха не меняет граф. Изменения HTML-копии альманаха не влияют на приложение или проекты.
