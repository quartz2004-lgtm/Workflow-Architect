# Workflow Architect 0.3.1 — надёжное фоновое выполнение

Статус: реализация начата. Выпуск ещё не готов.
Основание: утверждённый ROADMAP.md, раздел 0.3.1; распоряжение владельца сначала выпустить 0.3.1, затем вернуться к 0.4.0.

## Границы

Перенос существующего локального исполнения из жизненного цикла окна в фоновый процесс. Сохраняются существующие операции, контракты, лимиты и формат проектов 0.2. История запусков, контрольные точки, настройки сервиса и credentials не являются частью экспортируемого графа.

Подключение локальной языковой модели и приёмочный сценарий подготовки статей отложены до 0.4.0. Этот выпуск не добавляет Agent, сетевые коннекторы, Telegram или произвольные команды.

## Архитектура

- Electron main владеет жизненным циклом приложения, tray, настройкой автозапуска и проверкой отправителя IPC. Renderer остаётся sandboxed, без файлового и сетевого доступа.
- Отдельный процесс локального исполнения использует существующие compiler/executor. Окно подписывается на состояние и может переподключиться; закрытие окна не отменяет разрешённые фоновые задания.
- Версионированный протокол разделяет команды пользователя, состояния сервиса и события задания. Неавторизованные отправители, неверный профиль, неизвестные сообщения и чрезмерные payload отклоняются.
- Отдельное локальное хранилище фиксирует неизменяемый план, инициатора, журнал, контрольные точки, отмену и итог. Подтверждение команды следует за сохранением. Ошибка диска останавливает продвижение задания.
- Восстановление не считает незавершённую операцию успешной. Безопасное продолжение допускается только из проверенной контрольной точки; неоднозначный внешний эффект требует решения. Для нынешних чистых операций можно применять явно документированный безопасный повтор. Отмена сохраняется до следующего шага.
- Credentials шифруются средствами ОС, принадлежат профилю, передаются UI только как метаданные. Чтение секрета недоступно через публичный renderer API. Отзыв запрещает дальнейшее использование. Профили одного Windows-пользователя не являются ОС-изоляцией.

## Обязательная приёмка

- Разрешённый run продолжает работу после закрытия окна; повторное открытие показывает актуальные события без дублирования.
- Перезапуск сохраняет историю и различает завершённый, отменённый и прерванный run. Повреждённое или несовместимое состояние не исполняется.
- Отмена во время ожидания Human, закрытия окна и переподключения остаётся окончательной. Поздний ответ не возобновляет отменённый run.
- Общий timeout учитывает сон ПК; просроченный запрос Human не принимает ответ после пробуждения.
- Ограничения параллельности, размера журнала и общего диска проверяются на границе сервиса. Переполнение и ошибка записи видимы пользователю.
- Повтор одного входного события не создаёт второе задание; конфликт того же ключа с другим содержимым отклоняется. Неоднозначный внешний эффект не повторяется автоматически.
- Переключение профиля не меняет инициатора активного задания и не выдаёт чужие credentials.
- Автозапуск выключен по умолчанию и управляется явным выбором пользователя. Выход через tray имеет понятную семантику для активных заданий.
- Старые проекты открываются без потери данных, редактирование/undo/autosave/экспорт работают; текущий run использует исходный снимок.
- Проверены hover/focus, клавиатура, пустые состояния, ошибки, reduced motion и читаемость журнала.

Номер версии, тег и публикация разрешены только после прохождения приёмки; наличие плана или отдельных модулей не считается выпуском.

## Проверенные промежуточные результаты

- Добавлены AtomicStore (проверка схемы, атомарная замена, квоты, защита имён файлов) и чистая политика восстановления/ограниченных повторов. Они ещё не подключены к исполнителю и UI.
- 10 новых тестов проверяют файловое хранилище на реальном временном каталоге и решения восстановления.
- `npm run check`: copyright/notices, typecheck, lint, 116 unit-тестов и production build прошли. Это проверка фундамента, не приёмка фонового выполнения.
- Исполнитель поддерживает контрольные точки 0.3.1 с очередями, стеком Subworkflow, локальными результатами, Human request/answer, стабильными IDs и абсолютным timeout. Добавлены 8 сценариев восстановления, включая ожидание Human внутри вложенного графа и ошибку записи принятого ответа.
- После изменения исполнителя прошли typecheck/lint/copyright, production build, существующие unit-тесты и все 26 browser e2e. Фоновый менеджер заданий, процесс, UI истории и credentials остаются обязательными следующими этапами.
- Добавлен JobManager: запись плана/входа/профиля и согласия на фон, дедупликация, ограниченная очередь, публикация только сохранённого состояния, долговечная отмена, классификация прерванных записей и до трёх попыток восстановления. 13 новых тестов используют файловое хранилище. `npm run check` прошёл: 137 unit-тестов, typecheck/lint/copyright/notices и production build. Отдельный процесс, подключение desktop UI и credentials ещё не реализованы.
- Runtime вынесен в Electron UtilityProcess, bundle включён в desktop staging/installer; добавлены закрытый IPC, проверка sender/frame/origin, reconnect, tray, opt-in автозапуск и wake-проверка deadlines. Реальные desktop-тесты подтвердили выполнение после закрытия всех окон, отмену foreground run, восстановление после принудительной остановки процесса и отказ постороннему webContents. Прошли 138 unit-тестов и 8 desktop-тестов, typecheck/lint и сборки. Run UI пока ещё использует прежний Worker: следующим этапом он переключается на native service, получает историю и состояния подключения. Credentials и финальная приёмка installer ещё обязательны.
