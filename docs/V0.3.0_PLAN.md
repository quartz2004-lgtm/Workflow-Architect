# Workflow Architect 0.3.0 — контракт выполнения и приёмка

Основание: утверждённый ROADMAP.md, раздел 0.3.0. Дата начала: 12.10.2026. Это план новой версии, не заявление о завершении.

## Границы

Реальное локальное выполнение ручного Trigger, Data, Logic, Human, Artifact и Subworkflow. Agent, Tool, неразрешённые Concept и неподдержанные операции блокируют запуск с диагностикой на узле. Preview остаётся отдельной структурной симуляцией. Фоновый сервис, восстановление незавершённых запусков после закрытия, сетевые подключения, credentials и модели относятся к следующим этапам.

## Архитектура и порядок

1. Domain: типизированные декларативные настройки операций, версия проекта 0.2, чтение старого 0.1 через проверенную миграцию с исходным backup. Импорт/экспорт, recovery, копирование и undo сохраняют настройки.
2. Execution compiler: неизменяемый snapshot, собственная версия плана, проверка исполнимости и контрактов, маршрутизация портов, ограничения циклов и вложенности. Координаты и UI не участвуют в семантике.
3. Executor: независимая библиотека с транспортом Web Worker, статусы queued/running/waiting/succeeded/failed/cancelled, результаты каждой активации, события, явная отмена и лимиты. Никаких eval, shell, произвольных файловых путей или сетевых вызовов.
4. UI: формы операций и условий, отдельная команда запуска, входные данные, диагностика на узлах, ожидание человека, журнал и локальные артефакты. Редактирование рабочего графа не меняет текущий run.
5. Приёмка: рабочий пример с ветвлением и Subworkflow, unit/integration и browser/desktop сценарии, автономная справка, проверка компактного окна и клавиатуры, production build и hosted CI, обновление Windows и релиз v0.3.0.

## Семантика, которую нужно обеспечить

- Flow передаёт активацию и её JSON-значение. Несколько выбранных исходящих связей обрабатываются в устойчивом порядке; каждый приход является отдельной активацией. Это не обещание параллельных workers.
- Data передаёт результат указанного узла через порты, но не запускает узел. Недоступный результат — явная ошибка, а не undefined. Данные из разных вызовов Subworkflow не смешиваются.
- Tool access описывает разрешённую связь Agent → Tool; оба пока не исполняются. Reference — структурная ссылка, не активация и не чтение файла/сети.
- Условия и преобразования — типизированные операции над JSON, настраиваемые формами. Свободный JavaScript и прежние текстовые описания не исполняются. Неоднозначная конфигурация блокирует запуск.
- Цикл имеет условие выхода и максимальное число итераций. Циклические пути без явного ограничителя блокируются компилятором; общий лимит шагов защищает весь запуск.
- Subworkflow исполняется в отдельном контексте входов/выходов; открытые порты сопоставляются с внутренними узлами. Рекурсивное включение запрещено. Ошибка содержит путь графа и узел.
- Human останавливает соответствующую активацию до подтверждения/ввода; данные ответа проверяются. Отмена и истечение timeout не разрешают продолжение поздним ответом.
- JSON Schema проверяется без генерации кода: поддерживаемое подмножество фиксируется явно; неизвестные исполняемые ограничения отклоняются до запуска, а не игнорируются. Informal-контракты остаются описаниями.
- Артефакты создаются из фактических значений, доступны для просмотра и сохранения через существующий Save As. Шаблон не превращается в исполняемый код; путь из графа не даёт доступ к файловой системе.
- Результаты и статусы run не записываются в project/history. Запуск хранит ID и зафиксированный план; последующее редактирование относится только к новому запуску.

## Обязательные доказательства завершения

- Старые JSON/YAML/ZIP, recovery и локальные проекты открываются; backup предшествует преобразованию; неизвестная версия и невалидная миграция не портят данные.
- Формы создают исполнимую цепочку без ручного редактирования JSON конфигурации. Настройки проходят editor commands, undo/redo, autosave и portable roundtrip.
- Ручной вход → ветвление → вложенный workflow → Human → артефакт; результат и ошибки проверяются по содержимому.
- Проверены оба исхода условия, ограниченный цикл и превышение лимита, несоответствие input/output/edge contract, недоступные Data, неверные порты и ссылки, отказ от Agent/Tool/Concept.
- Проверены отмена running/waiting, ошибочный и поздний ответ Human, timeout, независимость работающего snapshot от изменений редактора, повторный запуск без старых результатов.
- Проверены Worker/renderer границы, отсутствие eval и внешних действий, ограничение размеров входов/результатов/событий, обработка отказа worker.
- Проходят copyright:check, notices:check, typecheck, lint, unit/integration, browser, packaged/installed desktop, production build и CI. Документация описывает фактические ограничения.
- Опубликован проверенный тег и установщик с checksum; обновление сохраняет существующие проекты.

## Состояние

Начата разработка на ветке development/0.3.0 от v0.2.0. Реализация и выпуск ещё не завершены.

Первая итерация: декларативные схемы операций, собственные ссылки на порты, безопасные JSON Pointer/условия/преобразования и интерпретатор контрактов. Не подключено к editor/runtime; следующий шаг — версия проекта, миграция и компилятор. Проверки включают строгие типы, lint, copyright/notices, прежний regression suite и новые тесты операций/контрактов; production build сохраняет работающий редактор 0.2.0.

Вторая итерация: проект 0.2, frozen source schema 0.1 и backup перед миграцией; legacy JSON/YAML/ZIP и локальное хранилище. Тестируются отказ backup, несовпадающие версии пары, recovery, сохранение операций/условий, undo/redo и перенос ID портов при дублировании без изменения литералов. Пройдены 80 unit/integration tests и 23 существующих браузерных сценария. Это ещё не проверка нового runtime: его реализация следует далее.

Третья итерация: компилятор фиксирует независимый план версии 0.3. Проверены замораживание snapshot, отказ от неподдержанных узлов и старых текстовых условий, shared/informal contracts, ветви по ID портов, ограничители циклов, привязки/рекурсия Subworkflow, отдельная семантика Reference и Data. Пройдены 87 unit/integration tests, typecheck, lint и build. Исполнитель, transport Worker и интерфейс запуска остаются следующими этапами.
