## 0.5.1 — Telegram в одном окне

Откройте **Интеграции → Telegram · начать здесь**. В этом окне вводится защищённый токен, даётся разрешение текущему профилю, проверяется бот, получается одноразовая команда привязки и включается сценарий для личного чата. UUID переносить не нужно. Подробный путь — во встроенном альманахе, глава «Telegram, API, файлы и MCP».

Для **Статьи и правки · нужна Ollama** подключите и разрешите модель в текущем профиле через **ИИ-помощник → Подключение**. Модель в Agent должна совпадать с разрешённой. Подключение другого профиля не используется. Для проверки без модели есть **Подтверждение и файл · без ИИ**. Мастер проверяет входные поля и разрешённую модель до включения; доступность самой Ollama и динамические результаты проверяются пробным запуском.

Нажмите **Включить для этого чата**, затем **Отправить тестовое сообщение**. Бот покажет активный сценарий и кнопки. **Новый текст** ждёт тему следующим сообщением; **Правки** ждёт пожелание к последнему результату. **Сценарий**, **Статус**, **Последний файл**, **Остановить**, **Помощь** работают без модели. Ожидание темы/правок действует десять минут. Human подтверждается отдельными кнопками под вопросом. Неизменяемая версия обновляется только через **Подтвердить и обновить сценарий чата**.

HTTP/JSON, папки и MCP находятся в **Другие подключения**, расписания — в **Расписание и публикации**. Файловый MCP получает только выбранную папку и явно разрешённые инструменты. Произвольные команды серверов не принимаются. Приложение должно работать на включённом ПК; закрытие окна оставляет его в трее.

Native-настройки, публикации, диалоги и журналы находятся в `runtime/integrations`, отдельно от экспортируемого проекта. Формат проекта — 0.4. Перед обновлением сохраняется резервная копия userData. Установщик: `release/Workflow-Architect-0.5.1-Setup.exe`. Статус приёмки и выпуска — [V0.5.1_PLAN.md](V0.5.1_PLAN.md).

## Запуск

Установщик: `release/Workflow-Architect-0.4.0-Setup.exe`.

Установите для текущего пользователя и откройте **Workflow Architect** через ярлык на рабочем столе или меню «Пуск». Редактор и JSON-операции не требуют Node.js, терминала, сервера или интернета. Для ИИ отдельно нужна локальная Ollama и загруженная модель; интернет требуется при их установке.

Также можно запустить `release/win-unpacked/Workflow Architect.exe`. Для переноса этой версии нужна **вся папка** `win-unpacked`, а не один exe.

## Первые действия

1. При первом запуске пройдите настройку профиля или пропустите её. Затем нажмите название проекта сверху → выберите пример или создайте свой проект.
2. Добавляйте Concept и engineering nodes слева, связывайте порты, редактируйте свойства справа.
3. `Ctrl+K` открывает команды, `Ctrl+F` — поиск, `Ctrl+Z` — отмену. **F1 / ?** или кнопка **«Альманах»** открывает полное руководство из 32 глав с поиском. Его можно сохранить как автономный HTML для чтения и печати.
4. «Validate» показывает структурные ошибки; «Preview» демонстрирует обход графа без выполнения агентов.
5. «Экспорт» → выберите snapshot, архив, Markdown или Codex package → сохраните через стандартное окно Windows.
6. Для реального локального выполнения откройте пример «Первый локальный запуск», нажмите Run и запустите workflow. Подтвердите Human, раскройте артефакт и сохраните result.json. ИИ и сеть не требуются. Перед запуском явно разрешите продолжение после закрытия окна, если нужен фон. Без такого согласия закрытие окна отменит Run. История, журнал и артефакты сохраняются отдельно от проекта.

## Фоновый сервис 0.3.1

Приложение остаётся в системном трее после закрытия окна. Двойной щелчок возвращает редактор; меню позволяет открыть окно, явно включить автозапуск при входе в Windows или полностью выйти. Автозапуск выключен по умолчанию. Полный выход сохраняет прерванные задания; безопасные фоновые задания могут восстановиться при следующем запуске в пределах исходных 5 минут и трёх попыток. Сон ПК не продлевает deadline.

Run показывает историю активного профиля, состояние сервиса и кнопку переподключения. Одновременно работают два задания. Квота истории — 500 записей / 256 MiB; при заполнении сохраните результаты и удалите ненужные завершённые записи. Отмена окончательна. Повреждённые файлы сохраняются и не исполняются.

«Подключения» внизу редактора хранит секреты с Windows DPAPI, отдельно от проектов. В Tool → Authentication → credential-ref переносится только ID. Можно разрешить использование, отозвать доступ и удалить запись. В 0.4.0 локальная Ollama использует отдельную настройку без API-ключа; внешние адаптеры credentials ещё не используют.

## Локальная модель и ИИ 0.4.0

1. Установите [Ollama для Windows](https://ollama.com/download/windows), затем выполните `ollama pull qwen3:8b`. Для RTX 5070 с 12 GB памяти выбрана модель Qwen3 8B. Ollama и веса не входят в установщик Workflow Architect; их лицензии действуют отдельно.
2. Убедитесь, что Ollama запущена. Приложение обращается только к `127.0.0.1`, по умолчанию порт 11434. Учётная запись Ollama и облачная модель не нужны. Для режима только локальных моделей Ollama поддерживает пользовательскую переменную `OLLAMA_NO_CLOUD=1` с перезапуском сервера — [официальная инструкция](https://docs.ollama.com/faq#how-do-i-disable-ollama-cloud-features).
3. Внизу редактора нажмите **ИИ-помощник → Подключение**. Обновите список, выберите `qwen3:8b`, разрешите использование для текущего профиля, сохраните и нажмите **Проверить модель и инструменты**. Проверка действительно вызывает Tool и отдельно получает JSON по схеме. Разрешение у второго профиля независимое.
4. Название проекта → **Статья · Автор и редактор** → **Run**. Пример содержит двух агентов и разрешённый инструмент подсчёта слов. Полученный `article.md` сохраняется через панель артефактов. При выборе другой модели обновите её имя в обоих Agent.
5. Вкладка **Проектирование** принимает описание задачи, задаёт уточнения и показывает предложенные узлы/связи. Добавление происходит только кнопкой, единым шагом Undo. Право новых агентов на Tool включается отдельно.
6. Вкладка **Для меня** анализирует анкету и ваши впечатления от пробной задачи. Выберите один из 2–3 объяснимых вариантов, при необходимости отредактируйте и примените. Исходные настройки можно восстановить. ИИ не меняет секреты, разрешения или лимиты выполнения и не обучает веса модели.

Если модель недоступна, проверьте Ollama, порт и точное имя из списка. Ошибка контекста/лимита не означает обрезку входа: сократите контекст или осознанно увеличьте лимит Agent. При недостаточном объёме статьи запуск завершается с ошибкой и сохраняет журнал, а не выдаёт короткий текст за выполненную задачу. Подсчёт слов и редактура не проверяют факты через интернет.

Ограниченный Parallel предназначен для независимых Agent-ветвей: 2–8 ветвей, каждая сразу ведёт в один указанный Merge; 1–4 активных запроса. Ollama может ставить запросы в очередь в зависимости от памяти и своей конфигурации. Результаты объединяются в порядке ветвей, а не скорости ответов. Весь Run имеет общий deadline 5 минут. Прерванные ИИ-задания после аварии не повторяются автоматически: изучите журнал и запустите новый Run.

Telegram, HTTP и MCP запланированы в 0.5.0, работа с Git/VS Code/Codex и командами — в 0.6.0. Сейчас Tool исполняет только встроенную статистику текста.

## Данные

Проекты автоматически сохраняются в IndexedDB профиля `%APPDATA%\Workflow Architect`. При закрытии приложение сначала фиксирует редактируемое текстовое поле и завершает autosave. Если сохранение не подтверждено, выход требует явного выбора. JSON-поля сохраняются кнопкой «Применить JSON».

Desktop и браузер имеют отдельные хранилища. Для переноса используйте JSON/YAML snapshot или ZIP через менеджер проектов. Регулярный экспорт snapshot подходит для резервной копии. Деинсталлятор сохраняет профиль. Внутри userData папка `runtime/jobs` содержит историю и checkpoints, `runtime/ai-connections` — настройки локальной модели по профилям, `credentials` — зашифрованные секреты и метаданные. Они не входят в экспорт проекта. Профили приложения не изолируют программы одного пользователя Windows; перенос ciphertext на другую учётную запись/ПК не является резервным копированием ключей.

Приложение работает офлайн после загрузки локальной модели; внешние tools не выполняются. Экспортируемый пакет сохраняет описание workflow, а подключения и историю переносите отдельно. Старые проекты 0.1/0.2 мигрируют в 0.3 с исходной резервной копией. Установщик Alpha не имеет сертификата подписи издателя.

## Сборка из исходников

```sh
npm ci
npm run desktop:build
```

Результат появляется в `release/`. Первой сборке нужен интернет для загрузки Electron и NSIS. Для разработки desktop без установщика:

```sh
npm run desktop:prepare
npm run desktop:start
```

Проверки:

```sh
npm run check
npm run test:e2e
npm run desktop:prepare
npm run test:desktop
```

Desktop-тест запускает настоящее Electron-окно с отдельным временным профилем: CSP/bridge, ввод, закрытие без ожидания debounce, повторный запуск, ZIP-экспорт и повторный импорт. Для проверки установленной сборки задайте `DESKTOP_EXECUTABLE` абсолютным путём к exe перед `npm run test:desktop`.

Архитектурное решение: [ADR 0005](decisions/0005-windows-desktop.md).
