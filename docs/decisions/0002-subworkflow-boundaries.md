# ADR 0002: Вложенные графы и открытые порты

Статус: принято для Canvas organization.

## Решение

Команды получают scope графа от editor session. Один durable Project хранит корневой граф и `subworkflows[]`; navigationStore хранит только временный активный graph ID и breadcrumb. Patch history запоминает graph ID действия, поэтому undo/redo возвращает пользователя на соответствующий уровень.

Group → Subworkflow переносит узлы и внутренние связи с сохранением их UUID, полей и координат. ID группы становится ID wrapper node. Пересекающие границу связи сохраняют ID/контракт/label/condition и переподключаются к wrapper ports.

Порт wrapper может содержать `binding: { nodeId, portId? }`, указывающий во внутренний граф. Направление и тип такого порта проверяются валидатором. Этой информации достаточно для структурного экспортера, чтобы восстановить boundary mapping без чтения Canvas. Изменять координаты для выражения этой семантики не нужно. Поле `subworkflows[].ports` сохраняется для импортируемых определений интерфейсов; созданные редактором instances описывают границу своими wrapper ports.

References на tools/context/fallback разрешаются по всему Project, поскольку эти отношения могут пересекать границы подсистем. Обычные графовые edges остаются локальны одному графу. Tool access через wrapper разрешается по конечному binding и по-прежнему обязан связывать Agent → Tool. Удаление внутреннего узла каскадно удаляет его открытые ports/инцидентные внешние edges, в том числе через несколько уровней; всё восстановимо одним undo.

## Совместимость

Формат по-прежнему имеет `schemaVersion: "0.1"`. Новое поле `port.binding` optional: прежние снимки читаются без миграции и потери данных. Диапазон размеров Group расширен, поскольку группы могут охватывать много узлов; диапазон размеров обычных карточек не менялся. Это явное аддитивное развитие первой alpha-схемы, не переименование или удаление существующих полей. Старый strict reader не обещает чтения новых полей; при стабильном релизе последующие изменения требуют отдельного version/migration решения.

## Canvas

Domain хранит абсолютные координаты. XYFlow adapter вычисляет временные parentId и относительные координаты. При collapse участники скрываются только в проекции; boundary edges рисуются к группе, исходные edges не переписываются. Drag/resize переводятся обратно в domain coordinates. Canvas library types не выходят за `canvas/`.

## Copy/Paste

Clipboard содержит выбранный graph fragment, достижимые nested graphs и только используемые shared schemas/prompts. Duplicate генерирует новые IDs и переписывает структурные references; JSON Schema bodies и текст остаются неизменными. Вставка — одна транзакционная команда, проходящая общую структурную/семантическую проверку.
