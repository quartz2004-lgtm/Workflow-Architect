# ADR 0015: подключённая папка и локальные снимки знаний

Статус: принято для 0.5.2.

SOAR пополняется вне приложения. Копия репозитория в исходниках Workflow Architect быстро устареет и может попасть в Git/облако. Поэтому приложение хранит путь к разрешённой папке отдельно от экспортируемого проекта и копирует только явно выбранные UTF-8 Markdown/JSON в профильную коллекцию.

Снимок содержит исходный текст, хеш каждого документа, стабильный ID по коллекции/пути, исходные ID и SKU, точную версию базы и общий digest. Git HEAD не является версией содержимого. Утверждение/область сохраняются из исходных полей без автоматического обобщения. Каталог — производная проекция снимка, а не единственная копия данных. Полнотекстовый/векторный retrieval относится к 0.5.3.

Используется существующий AtomicStore с валидируемой записью коллекции, содержащей до трёх снимков. Это позволяет атомарно заменить текущую версию вместе с историей без отдельной транзакционной БД. Квоты ограничивают размер импортов, число файлов и историю; ошибки сохраняют прежнюю запись. Превью хранится только в памяти до подтверждения и связано с ожидаемой ревизией коллекции. Пользователь видит именно подтверждаемый снимок; повторное чтение папки не подменяет его.

Права задаются владельцем коллекции (профилем) и явным набором путей. Native IPC проверяет trusted sender и схемы; запрос чужого ID отклоняется. Профили приложения не являются отдельными аккаунтами Windows и не защищают файлы от владельца компьютера. Символические ссылки, архивные/служебные пути, исполняемые файлы исключены; импортированный текст — данные, не команды.

Резервная копия содержит знания в открытом JSON, что явно обозначено при экспорте; не содержит пути к подключению. Восстановление создаёт новую коллекцию текущего профиля, проверяет целостность и требует заново подключить источник для обновлений. Изменение/удаление исходника применяется только к новому снимку. В 0.5.2 нет запусков, ссылающихся на эти снимки; будущая политика run-артефактов проектируется отдельно.
