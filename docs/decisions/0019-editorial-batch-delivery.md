# ADR 0019: пакет материалов поверх обычной очереди runtime

Статус: реализуется в ветке 0.5.5, 02.11.2026.

## Решение

Пакет до десяти материалов — сохранённый список независимых запусков, а не одна большая задача модели. EditorialBatchService записывает исходный снимок графа, профиль, задания и стабильные ID до отправки. Каждый пункт проходит JobManager.submit и получает собственные досье, настройки редакции, историю, версии и Human.

Ключ события состоит из ID пакета и материала. Сбой между submit и записью подтверждения в списке устраняется повтором того же ключа; новые источники для уже принятого пункта не собираются. Частичная постановка видна по каждому пункту, повтор отправляет только ещё не принятые материалы. Для них источники фиксируются при успешной постановке, а не задним числом. Отмена списка сохраняется до отмены принадлежащих ему заданий. Одобрение и результат никогда не общие для всего пакета.

## Сроки

Новые записи 0.5.5 получают до 24 часов на первый старт. После первого dispatch фиксируется executionStartedAt и обычный deadline по плану. Ожидание Human и последующий простой входят в срок выполнения. Повторный запуск после сбоя не продлевает его. Старые записи без этих полей сохраняют прежние правила; формат проекта не меняется.

## Ограничения текущего шага

Сервис подключён к нативному IPC, пользовательский экран ещё не готов. Текущая параллельность runtime ограничивает также задачи, ожидающие Human: при занятых слотах нужно завершить или отменить ожидающее подтверждение. Это должно быть понятно показано в UI. Десять реальных статей и восстановление пользовательской очереди ещё требуют отдельной приёмки; синтетические проверки не закрывают этот гейт.
