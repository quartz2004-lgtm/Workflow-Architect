# ADR 0008: локальный runtime и долговечное состояние

Статус: принят для реализации 0.3.1. Это описание решения, не подтверждение готовности выпуска.

## Контекст

Worker 0.3.0 принадлежит окну; закрытие окна уничтожает выполнение и журнал. Для домашнего ПК нужны независимое выполнение, восстановление и сохраняемая отмена. Domain-модель и чистые операции уже независимы от Canvas.

## Решение

Electron main управляет отдельным процессом runtime и tray. Renderer общается только через узкий preload API. Main проверяет webContents, главный frame и origin каждого запроса, затем пересылает валидированную команду по приватному каналу процесса. Публичного TCP-порта нет. Закрытие редактора и полный выход приложения — разные действия.

Runtime хранит версионированные записи отдельно от IndexedDB проектов. Запись сначала проверяется схемой, записывается во временный файл, синхронизируется на диск, затем атомарно заменяет целевой файл. Подтверждения и переход к следующему действию допускаются только после успешного сохранения. Незавершённые временные файлы не принимаются за подтверждённое состояние. Повреждённые записи сохраняются для диагностики и не исполняются.

ExecutionRun формирует контрольную точку из стека вызовов, очередей ещё не завершённых активаций, локальных результатов портов, счётчиков Loop и Human request/answer. ID запуска, плана, активации, sequence и абсолютный deadline сохраняются. Точка создаётся при входе в граф, после полностью завершённого шага, при ожидании/принятии Human и отмене. Сервис обязан сохранять накопленные события вместе с контрольной точкой и только затем публиковать их подписчикам. Событие само по себе не является подтверждением долговечности. На восстановлении проверяются версия, план и связи кадров/узлов/портов. Завершённый run не возобновляется; новая попытка получает отдельное задание по явной политике.

Хранилище имеет квоту, учитывающую временные файлы и место для атомарной замены; не удаляет историю автоматически ради нового задания. Имена файлов образуются только из проверенных UUID. Один процесс владеет хранилищем; многопроцессная запись в один каталог не поддерживается. Повторное создание существующего ID запрещено.

Отмена — долговечное состояние, проверяемое до каждого действия. При старте сервиса незавершённые задания классифицируются отдельно от успешных. Чистые операции допускают безопасный повтор из контрольной точки. Внешний эффект, для которого не подтверждён результат, требует сверки либо решения пользователя. Ключ идемпотентности разрешает автоматический повтор только при подтверждённой поддержке адаптером и сохранении прежнего ключа; один лишь HTTP timeout не доказывает отсутствие эффекта.

Credentials хранятся отдельно, шифруются средствами Windows через Electron safeStorage и не выдаются renderer в операциях чтения. Профиль — принадлежность настройки, не отдельная граница безопасности Windows. При недоступном защищённом хранилище запись секретов запрещена.

## Следствия

Браузерная версия сохраняет ограниченный Worker режим и явно показывает, что закрытие вкладки прекращает выполнение. Desktop получает историю, переподключение и независимость от окна. Схема проекта 0.2 не меняется. Проверки должны включать фактическое завершение процесса, повторное открытие хранилища и установленный desktop, а не только mock transport.
