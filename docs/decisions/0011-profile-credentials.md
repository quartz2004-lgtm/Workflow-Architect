# ADR 0011: credentials вне проекта и runtime-журнала

Статус: принято для 0.3.1.

## Решение

Electron main владеет `CredentialVault`; отдельный bundle подключается только по фиксированному пути приложения. [Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage) предоставляет асинхронное шифрование Windows DPAPI. При недоступности шифрования plaintext fallback запрещён. Вращение ключа, запрошенное API, переписывает запись атомарно при загрузке.

Запись 0.3.1 содержит UUID, профиль, название, назначение, разрешение, ревизию, время и ciphertext. Лимиты: 100 записей, 64 KiB на запись, 8 MiB всего. Metadata и ciphertext не входят в domain project. Inspector хранит только существующую ссылку credential-ref; схему проекта менять не нужно.

Renderer вводит секрет один раз через ограниченную команду создания. В ответах получает только метаданные; команд чтения, расшифровки или копирования секрета нет. Копируется только ID. Main проверяет sender/frame/origin так же, как для runtime. Неизвестные команды и лишние поля отклоняются. Необработанные ошибки native API не возвращаются в renderer.

Разрешение по умолчанию выключено. Внутренний `resolve` проверяет принадлежность и permission перед расшифровкой и повторно после неё, учитывая ревизию. Отзыв во время асинхронной операции не должен выдать секрет. В 0.3.1 `resolve` не опубликован через native factory: внешние адаптеры ещё не существуют. Будущие доверенные адаптеры обязаны получать секрет заново перед действием и не кешировать разрешение.

Main держит известные plaintext-значения только в памяти для маскирования ошибок службы и отклонения секретов в submit/ответе Human до записи журнала. Удалённое значение остаётся в наборе маскирования до завершения процесса. Это защита известных значений и распространённых форматов, а не универсальный DLP. Вручную помещать секреты в произвольные поля проекта по-прежнему запрещено.

## Границы и проверки

Профили разделяют владение и списки, но не являются безопасными аккаунтами: оба доступны одному пользователю Windows. DPAPI не защищает от других программ того же Windows-пользователя. Удаление локальной записи не отзывает токен у внешнего провайдера.

Unit-тесты проверяют зашифрованный диск, metadata-only ответы, permission/revocation race, недоступное шифрование, повреждённые записи и ротацию. Desktop-тест использует реальный DPAPI и исключительно синтетический ключ во временном userData; проверяет UI, перезапуск, ID clipboard, отсутствие команды resolve и блокировку секрета до runtime-журнала.
