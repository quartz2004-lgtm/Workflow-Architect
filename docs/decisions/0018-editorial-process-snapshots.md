# ADR 0018: снимок редакционных настроек при постановке задания

Статус: принято в ветке 0.5.5, 02.11.2026.

## Контекст

Редакционные настройки профиля могут измениться, пока задача ожидает выполнения или восстанавливается после перезапуска. Использование текущих настроек на каждом этапе сделало бы результат невоспроизводимым. Одновременно отзыв разрешения на пример должен действовать и на незавершённые задания.

## Решение

Единственный нативный EditorialProcessService управляет версионируемой библиотекой профиля. JobManager фиксирует выбранные инструкции, параметры и принятые примеры в preparedProcess при enqueue. Runtime recordVersion 0.5.5 связывает снимок с processDigest; старые записи не получают настройки задним числом.

Каждый следующий вызов модели повторно проверяет разрешения примеров, но использует исходный снимок. Выбор другой версии влияет только на новые задания. Отзыв блокирует дальнейшую генерацию с примером, сохраняя историю. Прервать уже законченный вызов или изменить полученный текст отзыв не обещает.

UI и внешние входы используют одну нативную границу. Сохранение версии не означает выбор, сохранение примера не означает принятие, правка текста не означает обучение.

## Проверка и последствия

Runtime-тесты проверяют перезапуск, смену выбора, отзыв между этапами и повреждение снимка. Браузерный тест использует реальное файловое хранилище через заменённый bridge. Проверка упакованного приложения и пользовательская приёмка остаются отдельными этапами выпуска.

История занимает больше места, зато сохраняет точные инструкции. Новые форматы сценариев должны использовать тот же путь снимков и проверок, не создавать альтернативное хранилище в UI.
