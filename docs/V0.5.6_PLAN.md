# 0.5.6 — Понятное рабочее пространство

Статус 04.11.2026: установленный 03.11 кандидат не принят по глубине обучения. Владелец требует практические действия с автоматической проверкой и уровни с подуровнями. Исправление разрабатывается в той же 0.5.6; версия не опубликована. Основа — выпущенная 0.5.5. Улучшение качества модели и реальные длинные контентные испытания остаются в 0.6.3.

## Практическое обучение: исправление после обратной связи

04.11.2026 исправленный кандидат установлен. Проверки: 443 unit passed / 7 opt-in skipped, 47 browser passed (12 практических уроков), 19 packaged Windows passed, отдельный smoke практики установленного приложения passed; typecheck/lint/copyright/notices/build успешны. Визуально проверен активный урок при 1100×800. Перед установкой проверены 212 файлов копии; установка не изменила их, app.asar совпадает с тестируемой сборкой. Это техническая проверка; пользовательская приёмка нового курса не получена.

В ветке добавлены четыре уровня и 12 уроков: Concept/связи/история; Agent/Trigger/Tool/Data/Human/Artifact; Logic/Subworkflow; настоящий локальный запуск с Human и файлом. Каждый шаг ожидает соответствующего состояния domain graph или runtime. Нажатие кнопки само по себе не считается выполнением. Схема урока отдельная, исходный проект сохраняется обычным autosave. Прогресс и завершённые уроки изолированы по профилю, незавершённый урок восстанавливается после перезапуска. Доступны подсказка, повтор и возврат к рабочему проекту; следующий шаг появляется автоматически. Подсветка не перехватывает ввод.

Уроки обучают базовой конфигурации всех восьми инженерных типов, а не всем возможным параметрам. Они не настраивают внешние сервисы за пользователя и не оценивают качество промптов. Подробные практикумы подключения модели, базы, Telegram и полного редакционного пути остаются обязательным предметом расширения и самостоятельной приёмки; одних обзоров для этого недостаточно. Предыдущие 35 browser / 18 Windows относятся к старому кандидату и не доказывают проверенность этой правки.

## Архитектура и порядок

Простой интерфейс использует существующие Editor Commands, Project Store, профильные подключения и runtime. Canvas остаётся инженерным представлением того же проекта. Черновик задания — отдельное состояние интерфейса по стабильному ID проекта внутри сессии профиля, не часть экспортируемого графа и не история Undo. Формы ввода и Human используют общий разбор контракта; окончательная проверка остаётся в runtime.

1. **Непрерывность задания.** Сохранить ввод при закрытии панели и переходах между проектами; изолировать профили. Добавить формы обычных входных контрактов с явным техническим режимом для сложных схем, примером и проверкой. Не обрезать данные при переключении режима.
2. **Рабочее пространство.** Понятные входы «создать», «изменить», «открыть сценарий», «подключения»; видимые профиль, состояние модели, текущая задача и результат. Существующие инструменты настройки открываются из общего маршрута без дублирования их логики. Проект, опубликованный сценарий, запуск и файл различаются.
3. **Подключения и восстановление.** Существующие Telegram, HTTP, MCP, локальная модель и знания: настроить → проверить → использовать. Первая настройка показывает конкретные изменения. Ясные статусы, ошибки со следующим шагом, точные источники/версии, история, отмена и повтор. Сохранение прав и подтверждений.
4. **Полный жизненный цикл.** Закрытие окна/трей/полный выход, состав резервных копий, импорт/экспорт и сохранение. Canvas §64 остаётся доступным; ошибки ведут к узлу. Обновление альманаха и словаря, клавиатура, компактное окно, reduced motion.
5. **Приёмка и выпуск.** Проверки типов, lint, copyright, unit, browser, packaged Windows и визуальный просмотр. Затем самостоятельные проходы обоих пользователей по UX_EVOLUTION.md; зафиксировать время, помощь и затруднения отдельно от технических тестов. Сборка, backup, установка, PR/CI/tag/release/SHA256.

## Матрица пользовательских путей

В объём 0.5.6 по дополнительному запросу владельца включено пошаговое обучение: первое предложение, пропуск/повтор, подсветка областей и стрелки, два маршрута, профильный прогресс и отдельная учебная схема. Обзор объясняет интерфейс, практика не меняет рабочий проект. Это не обучение весов модели.

| Путь | Ожидаемый результат | Проверка |
| --- | --- | --- |
| Ввод → настройки → возврат | Задание не потеряно; черновики проектов и профилей не смешаны | unit + browser |
| Обычный сценарий | Простые поля вместо JSON; ошибки схемы понятны; сложный ввод доступен явно | unit + browser + Windows |
| Создать / изменить текст | Выбран сценарий, видны профиль и готовность; точная версия и источники доступны | browser + самостоятельный проход |
| Подключения | Выбрать, проверить и использовать без переноса ID; права остаются видны | browser + Windows + оба пользователя |
| История / ошибка / отмена | Результат находится, причина и следующий шаг понятны, неизвестный вызов не повторяется автоматически | browser + Windows |
| Canvas и перенос проекта | Создать, назвать, соединить, переместить, открыть Inspector, добавить, экспортировать/импортировать | существующие регрессии + UX |
| Закрытие / обновление | Понятны фоновые задачи и полный выход; копия не обещает отсутствующие данные | Windows + оба пользователя |

Самостоятельная приёмка не заменяется подсказками разработчика или mock-тестом. Новые провайдеры, обучение весов и полный перенос установки не входят в 0.5.6. Непройденные пункты не объявляются готовыми из-за номера версии.
