# 0.5.4 — Автономная редакция и понятное задание

Статус: разработка, не выпущено. Основание: ROADMAP.md, UX_EVOLUTION.md и поручение владельца выпустить 0.5.4. Ветка development/0.5.4 включает эволюцию roadmap из ba5011e.

## Архитектура и порядок

1. Независимые контракты редакционного задания, проверки и версий. Manual/Telegram используют один нормализатор; служебные Telegram ID не становятся содержимым статьи.
2. Ограниченный редакционный исполнитель: планировщик, писатель, проверяющий с раздельными запросами; максимум два исправления после первого черновика. Общий бюджет и локальные контрольные точки. Частичный ответ сохраняется, но не считается успешным.
3. Подключение к существующим domain/compiler/runtime. Формат проекта меняется только с миграцией и сохранением прежних схем. Завершённые этапы восстанавливаются; незавершённый внешний вызов не выдаётся за завершённый и не повторяет побочные эффекты.
4. Точное подтверждение версии/хеша через Human, история запросов и ответов. Правка отменяет прежнее одобрение. «Требуется редактура» сохраняет черновик, запрещает автоматическую публикацию.
5. Понятное задание, каталог товаров, предварительный просмотр досье, причины недоступности фото; технические настройки отдельно. Показать локальный режим, не имитировать Codex.
6. Сквозная приёмка, настоящая Mistral/SOAR, документация, проверки, PR/CI, установщик, тег и GitHub release. Установка только после штатного выхода, с резервной копией.

Фундамент domain остаётся независимым от React/Canvas и файловой системы. Сервис модели внедряется через ModelProvider; сведения источников фиксируются существующим KnowledgeRuntime. Редакционные состояния не хранятся в Canvas и не подменяют опубликованный снимок workflow.

## Начальные находки

- Текущий runtime ограничивает весь запуск 300000 мс; для нескольких этапов Mistral это слишком мало. Новый предел должен быть конечным, проверяемым и совместимым со старыми заданиями.
- Текущий executor запрещает восстановление активного Agent; нужны отдельные редакционные checkpoints, а не молчаливый повтор всей цепочки.
- runAgent отклоняет частичный/короткий текст; редакционному пути нужно сохранять такие ответы для версии и исправления, не ослабляя контракт обычного Agent.
- Действующий проект имеет schemaVersion 0.5. Прежде чем добавить новый исполняемый контракт, требуется ADR и миграция.

## Прогресс

Первый этап: src/editorial содержит валидируемое общее задание, формальные проверки, точное одобрение версии и отдельный пошаговый исполнитель planner/writer/reviewer. Он сохраняет intent до вызова, ограничивает генерацию тремя версиями, не накапливает ошибочную беседу, сохраняет частичный текст и не повторяет запрос с неизвестным исходом. Пока это независимый модуль: runtime, UI, Telegram, реальная модель и выпуск ещё не подключены/не проверены.

Проверки первого этапа: 15 новых тестов, весь набор 296 passed / 1 skipped; typecheck, lint, copyright/notices и production build прошли. Тесты используют искусственный ModelProvider и не доказывают художественное качество или работу настоящей Mistral.

Следующий шаг: интеграционный контракт операции и versioned migration, runtime checkpoint редакции, идентификация digest модели, точное Human-подтверждение и новый лимит общей длительности с совместимостью прежних записей.
