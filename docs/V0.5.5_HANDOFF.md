## Что делать при возобновлении

1. Прочитать эту запись, `V0.5.5_PLAN.md` и актуальный `ROADMAP.md`; проверить Git и реальные процессы. Не считать старый process handle работающим.
2. **Не возобновлять автоматически многочасовую матрицу.** Прежний будущий вариант `writer-utf8-600s` не запускать по инерции: увеличение таймаута не исправляет выдуманные свойства. Повреждённые `writer-candidate-2/3` запрещены preflight.
3. В существующем этапе **0.6.3** провести короткую диагностику рецензента: конкретное неподтверждённое утверждение должно быть обнаружено, корректный текст не должен отвергаться. Отдельно проверить бюджет исправления. При отсутствии эффекта исследовать организацию проверки/модель, а не бесконечно расширять промпт. Последний кандидат полного эксперимента пока не зарегистрирован; прежний план смены только таймаута требует пересмотра до регистрации. Прошлые неудачи не исключать по причине плохого качества.
4. В **0.5.5** оставить приёмку рабочего профиля: утверждённые эталоны для точных заданий, закрытый контроль, реальные оценки двух пользователей и очередь десяти отдельных статей с Human/восстановлением. Полная матрица и критерии отчёта остаются обязательными для заявления о качестве; менять план только явно, сохраняя все неудачи и знаменатели.
5. В **0.5.6** продолжить понятный путь результата, замечаний, источников и следующего действия. Не переносить туда блокер текущего сценария ради формального выпуска 0.5.5.
6. После содержательной приёмки: обновить версию и документацию, собрать и проверить распространяемый установщик, сделать резервную копию, установить с согласованным выходом приложения, получить приёмку, выполнить release/tag/контрольные суммы. Сейчас ни один из этих финальных шагов не объявлен выполненным.

Новых версий для остатка не добавлено. Подробные критерии качества не понижены. Пауза означает сохранённую незавершённую работу, а не готовый выпуск.
