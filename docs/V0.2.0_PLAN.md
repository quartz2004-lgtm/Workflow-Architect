# Workflow Architect 0.2.0 — план реализации и приёмка

Основание: утверждённый владельцем 09.10.2026 ROADMAP.md, этап 0.2.0. Реализация начинается с 0.2.0-alpha.1. Runtime, LLM и реальные интеграции в эту версию не входят.

## Порядок

1. Данные: атомарная защита от перезаписи чужих изменений, восстановление/сохранение своей копии; fixtures формата 0.1, явный migration pipeline и backup до преобразования; согласованные квоты переносимых snapshots и ZIP.
2. Редактор: единый реестр пользовательских команд для клавиатуры, палитры и контекстного меню; доступность и область действия команд проверяются одинаково.
3. Профили: отдельная локальная модель настроек, первый и второй именованные профили, переключение без потери несохранённых правок; настройки не попадают в project export.
4. Первая настройка: цели, задачи, опыт, предпочтения управления, доступные сервисы, небольшая пробная задача; пропуск, повтор и ручное изменение. Рекомендации этой версии детерминированы, подключения к ИИ нет.
5. Open source: выбранная владельцем лицензия, CONTRIBUTING, SECURITY, issue templates, сведения о зависимостях; выбранный владельцем remote и успешный hosted CI.
6. Выпуск: документация, браузерные/desktop проверки, установка обновления и tag 0.2.0 после полной приёмки.

## Проверяемые критерии

- Два экземпляра редактора не могут молча перезаписать изменения одного проекта. Конфликт сохраняет обе версии и даёт понятный путь продолжения.
- Проекты 0.1 из фиксированных примеров открываются без потери графа/ресурсов. Неизвестные версии отклоняются без записи. Преобразованию предшествует сохраняемая исходная копия; ошибка не уничтожает оригинал.
- Каждый поддержанный экспортируемый переносимый формат имеет явную проверку совместимых import/export квот. Крупная локальная работа остаётся доступной для восстановления/backup, даже если превышает переносимую квоту.
- Команды в разных UI-поверхностях выполняют одинаковые действия, учитывают выделение и сохраняют обычное редактирование текста.
- Два профиля сохраняют собственные имя, предпочтения, детализацию, шаблоны и рекомендуемые лимиты. Перезапуск и переключение не смешивают данные.
- Первый запуск позволяет пройти настройку или пропустить её; повтор и ручное редактирование доступны из приложения. Пробная задача не портит текущий проект.
- Предпочтения реально отражаются в интерфейсе/создаваемых проектах; рекомендации будущих лимитов честно обозначены как пока не исполняемые.
- Нет зависимости базовой работы от аккаунта, ключа API или сети.
- Typecheck, lint, unit/integration, browser, desktop и production build проходят. UI просмотрен в обычном и компактном окне, с клавиатурой и reduced motion.
- Лицензия выбрана, инструкции сборки воспроизводимы; upstream и hosted CI подтверждены внешними результатами. Пока этих результатов нет, 0.2.0 не объявляется полностью завершённой.
