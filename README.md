## Интеграции 0.5.0

В **Интеграциях** создаются профильные подключения Telegram, HTTP/JSON, папки статей и встроенного MCP filesystem server. Проверка подключения и отдельные разрешения инструментов доступны в интерфейсе. В Tool выбирается реальное действие и источники полей Flow/Data; Agent может вызвать только разрешённые Tool. Секреты, адреса разрешённых корней и права остаются вне проекта.

Для Telegram откройте **Интеграции → Telegram · начать здесь**. В одном окне: защищённый ввод токена и разрешение → проверка бота → команда привязки личного чата → готовый сценарий → **Включить для этого чата** → тестовое сообщение. Токен, ID подключения или публикации переносить между окнами не нужно. Для статей выберите **Статьи и правки · нужна Ollama**, для проверки без модели — **Подтверждение и файл · без ИИ**. Несовместимый вход вроде `/approved` обнаруживается до включения.

В боте доступны кнопки **Новый текст**, **Правки**, **Сценарий**, **Статус**, **Последний файл**, **Остановить**, **Помощь**. После «Новый текст» или «Правки» отправьте задание следующим сообщением в течение десяти минут. Навигация и выбор действия не требуют модели; Agent требует. `/help` возвращает меню, прежние команды сохраняются. Human подтверждается отдельными кнопками под вопросом. Изменения Canvas применяются к Telegram только через **Подтвердить и обновить сценарий чата**; активная версия видна в приложении и боте. Расписание настраивается отдельно и работает, пока приложение запущено, включая трей.

Повторная доставка Telegram не создаёт вторую задачу. Неопределённый исход внешней записи показывается для ручной сверки и не повторяется автоматически. Встроенная запись файлов проверяет хеш предыдущей версии; MCP `write_file` допускает перезапись внутри разрешённой папки при явном разрешении этого инструмента. В 0.5 нет удалённого shell, Codex/VS Code, групповых ботов или произвольных команд MCP. [Архитектурное решение и ограничения](docs/decisions/0013-native-integrations-and-durable-sources.md).

## Возможности 0.4.0

Windows-приложение выполняет Agent через локальную Ollama: последовательные цепочки, ограниченные параллельные ветви с одним Merge, контекст текущего запуска, JSON Schema для результата и явный доступ к встроенному инструменту статистики текста. Лимиты времени, токенов, вызовов модели/инструмента и отмена контролируются runtime; журнал показывает реальные вызовы и расход токенов. Незавершённые ИИ-запросы после аварии автоматически не повторяются.

**ИИ-помощник** внизу редактора объединяет подключение и проверку модели, проектирование графа по описанию и персональную настройку по анкете/пробной задаче. Предложения показываются до применения; добавление графа отменяется через Undo. ИИ предлагает 2–3 варианта предпочтений, доступно ручное редактирование и восстановление исходных настроек. Это анализ ответов, а не обучение весов модели.

Для первого ИИ-запуска установите [Ollama](https://ollama.com/download/windows), загрузите `qwen3:8b` командой `ollama pull qwen3:8b`. В **ИИ-помощник → Подключение** выберите модель, разрешите использование и выполните проверку. Затем название проекта → **Статья · Автор и редактор** → **Run**. Тема примера — «Как выбрать бельё для комфорта», минимум 600 слов; результат — `article.md`. [Подробная настройка](docs/DESKTOP.md), [приёмка 0.4.0](docs/V0.4.0_PLAN.md).

Run исполняет ручной Trigger, преобразования Data, If/Switch/Loop/Merge, Human, Artifact и Subworkflow в отдельном процессе Windows; браузер сохраняет Worker-режим. Формы не требуют кода; запуск фиксирует snapshot, показывает входы/выходы и сохраняет реальные результаты. Preview остаётся отдельным обходом архитектуры. [Критерии приёмки 0.3.1](docs/V0.3.1_PLAN.md).

Фоновый сервис сохраняет задания, журнал и контрольные точки. Перед запуском можно разрешить продолжение после закрытия окна; приложение остаётся в трее. История профиля, долговечная отмена, безопасное восстановление, переподключение и добровольный автозапуск доступны в Windows. «Подключения» хранит секреты отдельно от проектов с шифрованием Windows и отзывом разрешения. Ollama работает без API-ключа; Telegram/HTTP/MCP доступны с 0.5.0; Git/VS Code/Codex остаются этапом 0.6.0.

Чтобы попробовать: название проекта → **Первый локальный запуск** → **Run** → **Запустить workflow** → подтвердите Human → раскройте артефакт и сохраните `result.json`. Входные данные уже заполнены примером; смените `approved` на `false`, чтобы проверить вторую ветвь.

## Альманах

Кнопка **«Альманах»** в нижней панели или **F1 / ?** открывает встроенное руководство: 33 главы с оглавлением и полнотекстовым поиском. Назначение приложения, первый проект, все узлы и поля, связи, контракты, примеры, Validate, Preview, Run, ИИ, экспорт, хранение, восстановление и словарь.

[Полная HTML-версия для чтения и печати](docs/Workflow_Architect_Almanac.html) работает офлайн. Её также можно скачать кнопкой «Сохранить альманах» в приложении. Источник глав — `src/help/content.ts`; `npm run docs:almanac` обновляет HTML из него.

Значки **?** у полей открывают краткую справку мышью или с клавиатуры. «Подробнее в альманахе» ведёт к соответствующей главе. Общие тексты находятся в `src/help/field-help.ts`.

## Что работает

- Concept Node и Note: создание, описание, заметки, изменение размеров.
- Flow-связи между портами, подписи связей, удаление.
- Pan, zoom, snapping, выделение рамкой, Shift для множественного выделения, minimap.
- Изменения через команды; undo/redo, включая групповое перемещение и удаление связанных элементов.
- IndexedDB autosave с debounce, статусом и повтором после ошибки; открытие последнего проекта при запуске.
- Экспорт ZIP-проекта, JSON/YAML snapshot, Markdown architecture и Codex package с предпросмотром файлов и диагностикой.
- Безопасная остановка загрузки повреждённых данных с доступом к исходному JSON.
- Все восемь engineering types, конфигурационные Inspector-секции, Concept → Engineering conversion с undo/redo.
- Flow/Data/Tool access/Reference, портовые типы и направления, informal/JSON Schema/shared-schema contracts.
- Общие schemas/prompts; JSON Schema draft-07/2020-12 meta-validation; полноэкранный Markdown prompt editor и скачивание `.md`.
- Живая панель Validate, статусы предупреждений/ошибок на узлах, переход к проблеме в корневом Canvas.
- Создание, открытие и импорт локальных проектов через название проекта в верхней панели. При совпадении ID импорт создаёт отдельную копию.
- Группы: перемещение участников, collapse/expand, ungroup, Group → Subworkflow с сохранением boundary-связей.
- Вложенные Canvas с breadcrumb, настройка exposed-port bindings, переход к вложенным узлам через поиск/диагностики.
- Command Palette, контекстные меню, копирование/вставка/дублирование, глобальный поиск, alignment guides и восемь операций выравнивания/распределения.
- Обратный импорт ZIP, JSON/YAML snapshot и пары `project.json` + `workflow.json`, включая вложенные графы и shared resources.
- Три примера архитектуры, локальный JSON-пример и ИИ-пример статьи; подсказки первого запуска и настройки экспорта по умолчанию.
- Частичное восстановление JSON 0.1/0.2/0.3/0.4 в новую копию с отчётом и доступом к исходным записям; повреждённый оригинал сохраняется.
- Архитектурный Preview с паузой/шагами, branches и вложенными графами; без исполнения моделей, инструментов или условий.
- Автовысота по содержимому, подсветка совместимых портов, конвертация выбранных Concept через палитру.

Панорамирование: средняя/правая кнопка мыши; масштаб: колесо/Canvas controls. Двойной клик по фону, Space или `Ctrl/Cmd+K` открывает палитру команд; двойной клик по Subworkflow открывает его внутренний граф. Поля Inspector применяются при потере фокуса; Enter применяет однострочное поле. `Ctrl/Cmd+Z` — undo, `Ctrl/Cmd+Shift+Z` — redo; Delete/Backspace удаляет выделение, Escape снимает его. `G` группирует, `F` показывает граф, `Shift+F` — выделение, `Ctrl/Cmd+F` открывает поиск. `?` открывает всю справку. В текстовых полях действует обычное редактирование текста.

Сохранение локально для конкретного браузера и origin. До завершения debounce последние изменения могут быть потеряны при аварийном закрытии; после статуса «Сохранено» они записаны в IndexedDB. Удаление данных сайта удаляет локальное хранилище. JSON-снимок пригоден для резервной копии и повторного импорта. Если сохранение текущего проекта не удалось, переключение проекта останавливается, сохраняя правки в памяти.

## Проверки

```sh
npm run check
npx playwright install chromium
npm run test:e2e
npm run test:performance
```

Для приёмки на установленной Ollama: `npm run test:ai:local`. По умолчанию используется `qwen3:8b`, порт 11434; переменные `WORKFLOW_AI_MODEL` и `WORKFLOW_AI_PORT` меняют выбор. Результаты статьи, журнал и снимки — в игнорируемой папке `output/ai-acceptance`. Этот набор требует настоящую модель и не подменяет её mock-сервером; обычный CI проверяет транспорт отдельно.

`check` проверяет copyright-заголовки, notices зависимостей, typecheck, lint, unit/integration tests и production build. Playwright проверяет Canvas, engineering, экспорт, восстановление, профили и первую настройку. Desktop suite проверяет закрытие с сохранением, повторный запуск, офлайн-справку и настройки профиля. Результаты и снимки сохраняются в test-results/ и desktop-results/. Performance profile 100/300 nodes запускается отдельно без параллельной нагрузки; [методика](docs/PERFORMANCE.md).

## Границы Alpha

Модель и UI поддерживают все engineering types и их конфигурации, группы, вложенные графы и экспорты. Preview обходит структуру, не вычисляя условия. Recovery работает с распознаваемым JSON версии 0.1/0.2/0.3; неизвестные версии и неразбираемый JSON доступны как исходный файл. Проверки контрактов охватывают синтаксис JSON Schema и ссылочную целостность; полная проверка логической совместимости произвольных JSON Schemas не реализована. Clipboard локален открытой вкладке; внешние ссылки при переносе между проектами должны разрешаться в целевом проекте либо попадать в копируемое выделение.

Профиль Canvas 100/300 узлов проверяется отдельно; [методика и результаты](docs/PERFORMANCE.md). Редактор рассчитан на desktop; мобильный редактор исключён спецификацией. Run ограничен 5 минутами и 10 000 шагами; для ИИ — дополнительно 32 вызова модели, 64 вызова Tool и 131 072 токена на run. Parallel поддерживает 2–8 независимых Agent-ветвей и не более четырёх активных запросов; реальная одновременная генерация зависит от Ollama и памяти GPU. В Windows разрешённые фоновые задания продолжаются после закрытия окна, история хранится на диске. Полный выход сохраняет прерванное состояние; восстановление безопасных JSON-заданий ограничено исходным timeout и тремя попытками. ИИ-задания после сбоя требуют нового запуска. В браузере журнал находится в памяти вкладки. Shell, внешние интеграции, MCP/Git/Codex и deployment относятся к следующим версиям. Редактор текста и подсчёт слов не заменяют проверку фактов.

## Перенос проекта

Кнопка «Экспорт» открывает выбор формата и предпросмотр. ZIP содержит metadata-only `project.json`, полный `workflow.json`, agents/tools/prompts/schemas и документацию. Codex ZIP дополнительно содержит `IMPLEMENTATION_PLAN.md`, `ARCHITECTURE.md`, `AGENTS.md`, `TOOLS.md`, `CONTRACTS.md`, `TASKS.md`.

Для импорта выберите ZIP или оба JSON-файла вместе в менеджере проектов. Каноническая пара содержит весь проект; остальные файлы — сгенерированные представления для реализации. Их отдельное редактирование не изменяет повторный импорт. Самостоятельный `project-snapshot.json` или YAML также импортируется одним файлом. Errors блокируют инженерные пакеты, но резервный snapshot доступен; Warnings не блокируют экспорт.

Подробнее: [архитектура](docs/ARCHITECTURE.md), [план итераций](docs/IMPLEMENTATION_PLAN.md), [решение о формате и границах](docs/decisions/0001-domain-first-foundation.md).

Локальные snapshots больше 64 MiB открываются без ограничения внешнего импорта. Внешние JSON/YAML/ZIP по-прежнему ограничены 64 MiB (распакованный ZIP — 128 MiB); резервные файлы больше этого лимита нельзя повторно импортировать через текущий интерфейс. Большие файлы сохраняйте, исходные локальные записи не удаляйте.
